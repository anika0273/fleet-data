# What is ETL?

1. Extract: Retrieving raw data from one or more source systems.
   In this project, data is generated by the synthetic data generator or it can be collected from real fleet telemetry devices and supply chain management systems.

2. Transform: Cleaning, filtering, enriching, and reshaping the extracted data into a useful format.

   - Transformation: This includes:

     - Data type conversions and format standardization.
     - Derived feature creation (calculations, aggregations).
     - Filtering unwanted records or noise.
     - Joining or enriching data from multiple sources.
     - Data quality improvements for consistency.
     - Sometimes advanced steps like deduplication or pivoting.

   - Advanced Analytic Steps Possible But Usually Separate:
     - Statistical analysis (e.g., summary statistics, anomaly detection) may be performed, often integrated in transformation or as a separate analytic job.
     - Machine Learning (ML) model inference can be part of streaming ETL pipelines, e.g., scoring incoming records to detect fraud or risk in real-time. However, model training typically happens outside ETL, in dedicated batch or offline ML pipelines using the cleaned and prepared data. Feature engineering for ML is usually integrated in transformation or extracted as precomputed features to improve training and inference efficiency.

3. Load: Writing the transformed data into a target storage system like a data warehouse, database, or data lake for downstream consumption.

   ## Viewing Data from Both Batch and Streaming ETL on Dashboards

   - Storage

     1. Streaming ETL outputs:
        Streaming pipelines write to fast, low-latency storage suited for real-time queries, e.g., time-series databases (e.g., InfluxDB, TimescaleDB), NoSQL stores (e.g., Cassandra), or streaming-optimized sinks (e.g., Kafka topics, Elasticsearch).

     2. Batch ETL outputs:
        Batch jobs typically write to data warehouses or data lakes (e.g., Snowflake, BigQuery, Redshift, HDFS) optimized for complex queries and historical aggregation.

   - Dashboarding
     1. Dashboards can query both the streaming layer (for real-time monitoring) and batch layer (for historical trends).
     2. Modern BI tools (Tableau, Power BI, Grafana) support federated queries across multiple data sources.
     3. Combined dashboards can show:
        - Live alerts and recent sensor events (from streaming ETL).
        - Daily/monthly summaries, trends, and KPIs (from batch ETL).
     4. Sometimes data virtualization or data lakehouses (e.g., Delta Lake) unify data queries.

# Batch ETL

- Deals with processing data in chunks or batches (e.g., hourly, daily, or weekly).
- Typically handles large volumes once data is accumulated rather than processing every single event immediately.

## Purpose in Production

- Consolidate and clean bulk data to make it analytics-ready.
- Run large-scale transformations or aggregations which don’t require immediate freshness.
- Load clean, aggregated, or enriched datasets into reporting or analytics platforms.

## How Batch ETL Fits this Project

- Periodically (e.g., every day or hour), the fleet and supply chain data generated is extracted in bulk. We can use AirFlow.
- Operations like summarizing daily shipment delays, computing average fuel consumption by vehicle groups, or cumulative downtime per fleet are performed.
- The result is loaded into a database or warehouse where analysts or BI tools run queries for dashboards and strategy.

# Streaming ETL

- Deals with real-time or near-real-time processing of data events as they occur.
- Processes each event (e.g., a vehicle telemetry record, sensor alert, or shipment update) continuously and loads processed results incrementally.

## Purpose in Production

- Enable quick decision-making and alerting by providing up-to-date data.
- Support event-driven architectures and real-time dashboards.
- Facilitate automated operational responses (e.g., alert a driver immediately if harsh braking is detected).

## How Streaming ETL Fits This Project

- The synthetic data generator produces records continuously representing fleet telemetry and shipment events.
- Streaming ETL pipelines ingest each data event from Kafka (for this project) or similar streaming platform.
- Data is cleaned, enriched (e.g., mapping to driver or vehicle metadata), and streamed into real-time storage like a time-series database or streaming analytics platform.
- Operations teams monitor real-time dashboards and trigger alerts or interventions with minimal latency.

# Connection Between Batch and Streaming ETL

- Streaming ETL pipelines provide low-latency processed data for immediate operational insights.
- Batch ETL pipelines provide comprehensive and historical aggregated data for strategic and trend analysis.
- They complement each other: streaming ETL handles event-level freshness, batch ETL handles heavy aggregations and historical context.
- Both often source from the same raw data, stored in staging or event logs, but process on different cadences.

# Typical End-to-End Scenario

1. Data generation/source: Telemetry devices, sensors, or synthetic generators produce raw event data.
2. Ingestion: Streaming services like Kafka ingest raw events continuously.
3. Streaming ETL: Data pipelines consume the data live, apply lightweight transformations, detect anomalies or generate operational KPIs, then write to fast stores (e.g., Elasticsearch, timeseries DB).
4. Storage: Raw or lightly processed data is also stored in object storage or log systems for durability.
5. Batch ETL: On scheduled intervals (hourly/daily), batch pipelines extract stored raw or streaming data, perform complex transformations, enrich with reference data, and compute aggregated features and metrics at various levels.
6. Data warehouse/analytics: Cleaned batch data is loaded into analytics databases where dashboards, reports, and ML model training happens.
7. Operational response: Streaming analytics trigger real-time alerts, while batch analysis informs long-term decisions and model updates.
